# Legado书源表达风格与文化语境

## 一、术语体系

### 1.1 核心术语

| 术语 | 含义 | 使用场景 |
|:---|:---|:---|
| **书源** | 小说网站的解析规则 | 泛指 |
| **订阅源** | RSS/文章网站的解析规则 | 泛指 |
| **规则** | 提取数据的语法表达式 | 技术讨论 |
| **选择器** | CSS/XPath等定位元素的语法 | 技术讨论 |
| **净化** | 去除正文中的广告/无关内容 | 功能描述 |
| **调试** | 测试书源/订阅源是否正常工作 | 功能描述 |
| **发现** | App中的分类/排行榜页面 | 功能描述 |

### 1.2 技术术语

| 术语 | 含义 | 示例 |
|:---|:---|:---|
| **Default规则** | JSOUP原生语法 | `class.book-list.0@tag.a.0@href` |
| **CSS选择器** | CSS Selector语法 | `@css:.book-list li` |
| **XPath** | XML Path Language | `@XPath://*[@id="content"]` |
| **JSONPath** | JSON数据查询语言 | `@json:$.data.books[*]` |
| **AllInOne** | 正则提取多字段 | `:href="([^"]*)"[^>]*>([^<]*)` |
| **OnlyOne** | 正则提取单字段 | `##正则##替换###` |

## 二、表达风格

### 2.1 规则编写风格

**推荐风格：**
- 简洁明了，避免过度复杂的嵌套
- 优先使用CSS选择器，必要时使用XPath
- 正则表达式添加注释说明
- 变量命名清晰

**示例：**
```
// 好的风格
@css:.book-list li@href

// 避免过度复杂
class.book-list.0@tag.li.0@tag.a.0@href
```

### 2.2 错误提示风格

当书源出现问题时，常见的表达方式：
- "搜索规则匹配不到元素"
- "详情页解析失败"
- "目录为空，请检查目录规则"
- "正文乱码，请检查编码设置"

### 2.3 社区交流风格

- **分享书源**：通常分享JSON格式的书源代码
- **求助**：提供书源代码 + 问题描述 + 目标网站URL
- **反馈**：说明Legado版本 + 复现步骤

## 三、文化语境

### 3.1 开源文化

Legado是典型的开源项目：
- **自由使用**：免费开源，无广告
- **社区贡献**：书源由社区共享
- **持续迭代**：版本更新频繁
- **透明开发**：GitHub上公开开发

### 3.2 书源共享文化

- **源仓库**：https://www.yckceo.com/ 是主要的书源分享平台
- **导入方式**：支持网络导入、本地导入、二维码导入
- **更新机制**：书源有更新时，用户需要重新导入

### 3.3 技术门槛

书源制作需要一定的技术基础：
- HTML/CSS基础知识
- 正则表达式基础
- 基本的JavaScript语法
- 浏览器开发者工具使用

### 3.4 法律边界

- **灰色地带**：书源本身只是解析规则，不存储内容
- **版权风险**：使用书源阅读受版权保护的内容存在风险
- **个人使用**：建议仅用于个人学习研究

## 四、用户画像

### 4.1 典型用户

| 类型 | 特征 | 需求 |
|:---|:---|:---|
| **普通读者** | 只使用现成书源 | 稳定、书源多 |
| **进阶用户** | 会简单修改书源 | 书源编辑功能 |
| **开发者** | 能制作新书源 | 完整的规则文档 |
| **贡献者** | 分享自制书源 | 书源分享平台 |

### 4.2 使用场景

1. **追更小说**：使用书源追网络小说更新
2. **离线阅读**：下载小说到本地离线阅读
3. **RSS订阅**：订阅博客、新闻网站
4. **本地阅读**：导入本地TXT/EPUB文件

## 五、沟通禁忌

1. **不要询问破解版**：Legado完全免费，无需破解
2. **不要索要盗版内容**：书源只是工具，不提供内容
3. **不要过度索取**：书源制作需要精力，请尊重贡献者
4. **不要传播失效书源**：及时更新或删除失效书源

## 六、表达DNA总结

- **技术导向**：讨论围绕技术实现，而非内容本身
- **实用主义**：关注规则能否工作，而非理论完美
- **社区协作**：鼓励分享和互助
- **持续学习**：网站结构变化需要不断更新知识
